# Chrome 英文网页翻译插件需求文档

## 1. 文档概述

### 1.1 产品名称

Chrome 英文网页翻译插件。

### 1.2 产品目标

为阅读英文网页的用户提供文章提取与 AI 翻译能力。用户可以在当前页面启动插件，提取页面中的主要文章内容，将其转换为 Markdown，并在浏览器侧边栏中以类似 ChatGPT 打字机效果的方式动态展示翻译结果。

### 1.3 目标用户

需要阅读英文新闻、博客、教程、文档及其他英文长文章的中文用户。

## 2. 产品范围

### 2.1 本期范围

- 在 Chrome 浏览器中运行。
- 对用户当前打开的英文网页执行文章提取。
- 识别文章标题、作者、正文、正文图片及原始页面地址。
- 将提取出的文章内容转换为 Markdown。
- 调用 AI 大模型将文章正文翻译为中文。
- 在浏览器侧边栏中动态展示翻译结果。
- 在本地持久化保存最近一次翻译结果。

### 2.2 非本期范围

- 翻译历史记录及历史记录管理。
- 多条翻译结果的收藏、搜索、分类或同步。
- 用户账户与跨设备同步。
- AI 服务商、模型和接口配置方案的具体选择。
- 代码结构、技术框架、接口协议及其他实现细节。

### 2.3 产品边界

- 插件仅处理用户当前激活页面中的主要英文文章内容，不对整个网站进行批量抓取或翻译。
- 插件面向具备明确文章主体的公开网页，包括新闻、博客、教程和文档等；搜索结果页、首页信息流、论坛列表、社交媒体信息流等非文章页面不属于保证支持范围。
- 插件仅提取当前页面中用户有权访问且浏览器已加载的内容，不负责绕过登录、订阅、付费墙、验证码或其他访问限制。
- 插件仅翻译识别出的文章标题和正文；作者名、图片地址、链接地址、代码内容及其他非自然语言内容原则上保持原样。
- 插件保留正文中的图片引用，但不下载、转存、编辑或翻译图片本身，也不保证失效或受访问控制的图片可正常显示。
- 插件不修改原网页内容，翻译结果仅在插件侧边栏中展示。
- 插件不提供原网页全文镜像、网页离线保存或附件处理能力。
- 插件仅保存最近一次成功翻译结果，不形成可查询、恢复或同步的历史记录。
- 翻译质量受原文质量、正文识别结果和 AI 大模型能力影响，不承诺达到人工专业翻译水平。

### 2.4 产品约束

- 运行环境限定为支持插件侧边栏能力的 Chrome 浏览器版本。
- 页面内容提取受网页结构和浏览器访问权限约束；浏览器内部页面、插件页面及其他禁止访问的页面不支持提取。
- 对大量依赖动态加载、嵌套页面或特殊排版的网页，可能无法完整识别正文、作者或图片。
- 发起翻译时需要可用的网络连接及可访问的 AI 大模型服务；相关服务不可用时，插件无法完成翻译。
- AI 服务可能对单次输入长度、请求频率和响应速度设有限制；超出限制时应向用户明确反馈，不得静默丢失正文。
- 打字机效果表示翻译内容逐步呈现，不代表固定的输出速度；实际速度受文章长度、网络状态和 AI 服务响应影响。
- Markdown 转换以保持内容语义和阅读顺序为目标，不要求完全还原原网页的视觉样式、字体、布局或交互效果。
- 图片展示依赖原图片地址持续有效，并可能受防盗链、授权、网络或跨域访问策略影响。
- 本地持久化结果仅在当前浏览器及当前插件数据未被清除时可用；卸载插件、清除插件数据或浏览器异常可能导致结果丢失。
- 最近一次成功结果仅在完整翻译完成后更新；提取失败、请求失败、用户中止或响应不完整时不得覆盖已有结果。
- 发送至 AI 大模型的内容应限于完成翻译所需的文章信息，不得包含无关页面数据；实际数据处理同时受所选 AI 服务条款约束。

## 3. 使用场景

1. 用户在 Chrome 中打开一篇英文文章。
2. 用户启动翻译插件并发起当前页面翻译。
3. 插件提取当前页面的主要文章内容，排除导航、广告、推荐列表、评论等非正文信息。
4. 插件将标题、作者、正文段落和图片整理为 Markdown 内容。
5. 插件调用 AI 大模型翻译文章正文。
6. 浏览器侧边栏打开，并以打字机效果持续展示翻译内容。
7. 翻译完成后，最终内容符合规定的输出格式。
8. 插件在本地保存该结果，并用它替换此前保存的最近一次翻译结果。

## 4. 功能需求

### 4.1 插件入口

- 用户应能从 Chrome 浏览器中启动插件。
- 插件应针对用户当前激活的网页执行内容提取和翻译。
- 翻译结果应展示在浏览器侧边栏中，避免覆盖或替换原网页。

### 4.2 主要文章内容提取

- 插件应提取当前页面的主要文章，而不是完整网页源内容。
- 提取范围应至少包括：
  - 文章标题；
  - 作者；
  - 正文段落；
  - 正文中的图片；
  - 当前页面原始 URL。
- 插件应尽量排除与文章无关的内容，包括但不限于：
  - 顶部或侧边导航；
  - 广告；
  - 页脚；
  - 推荐内容；
  - 评论区；
  - 登录、订阅及分享提示。
- 当页面未提供作者或无法识别作者时，作者字段允许为空，但最终输出结构必须保留。
- 当页面无法识别有效正文时，应明确告知用户当前页面无法提取文章内容，不应生成误导性的翻译结果。

### 4.3 Markdown 转换

- 提取出的文章结构应转换为 Markdown。
- 正文段落应保持原有阅读顺序。
- 原文中的标题、列表、引用、链接等结构应在可识别时保留其 Markdown 语义。
- 正文图片必须转换为以下格式：

```markdown
![alt](src)
```

- `alt` 应优先使用原图片的替代文本；原文没有替代文本时允许为空。
- `src` 应指向原图片资源地址，并确保脱离原页面上下文后仍能表达该图片的位置。
- 图片应保留在其对应的正文位置，不应统一移动到文章末尾。

### 4.4 AI 翻译

- 插件应将提取并转换后的主要文章内容提交给 AI 大模型进行翻译。
- 默认翻译方向为英文到中文。
- 翻译结果应忠实表达原文含义，保持文章段落顺序及上下文连贯性。
- 标题和正文文本均应翻译为中文。
- 作者名原则上保留原文，不强制翻译。
- Markdown 结构应在翻译后继续有效。
- 图片 Markdown、链接目标地址及其他非自然语言内容不应被错误翻译或破坏。

### 4.5 动态展示

- 翻译结果应在浏览器侧边栏中展示。
- 展示过程应采用类似 ChatGPT 的打字机效果，随着翻译内容产生而逐步更新，而不是仅在全部翻译完成后一次性显示。
- 动态展示期间应保持 Markdown 内容顺序稳定，已展示内容不应无故丢失或重复。
- 用户应能区分以下状态：
  - 正在提取文章；
  - 正在翻译；
  - 翻译完成；
  - 提取或翻译失败。
- 翻译完成时，侧边栏中的内容应形成一份完整、可连续阅读的译文。

### 4.6 最近一次结果持久化

- 插件无需保存翻译历史记录。
- 插件仅在本地持久化存储最近一次成功完成的翻译结果。
- 新的翻译成功完成后，应覆盖此前保存的结果。
- 用户重新打开插件时，应能查看最近一次成功完成的翻译结果。
- 翻译失败或未完成时，不应覆盖最近一次成功结果。
- 持久化内容至少应包含：
  - 文章标题；
  - 作者；
  - 原文链接；
  - 翻译后的正文；
  - 正文中的图片 Markdown。

### 4.7 异常反馈

插件应针对以下情况向用户提供清晰反馈：

- 当前页面不是可提取的文章页面；
- 页面没有可识别的主要正文；
- 页面内容无法访问；
- AI 翻译请求失败；
- 翻译过程意外中断；
- 最近一次结果读取失败。

错误反馈应便于用户理解当前状态，但不得将失败内容保存为最近一次成功结果。

## 5. 最终输出格式

翻译完成后的内容必须遵循以下结构：

```markdown
#[文章标题]

>**作者**：[]作者名
>**原文链接**：[原始文章URL]


[翻译后的正文]
```

格式要求：

- `[文章标题]` 替换为翻译后的文章标题。
- `作者名` 替换为提取到的作者名；无法提取时保留空值。
- `原始文章URL` 替换为当前文章的原始页面地址。
- `[翻译后的正文]` 替换为完整译文，并包含处于原文对应位置的图片 Markdown。
- 标题、作者、原文链接和正文的先后顺序不得改变。
- 最终输出不得混入状态提示、调试信息或与文章无关的页面内容。

## 6. 数据与隐私要求

- 仅保存最近一次成功的翻译结果，不建立历史记录。
- 最近一次翻译结果应存储在用户本地。
- 除完成 AI 翻译所必需的文章内容外，不应主动收集或上传其他网页数据。
- 不应将广告、评论、导航信息等无关内容发送给 AI 大模型。
- 用户应能明确知道当前页面内容将用于发起 AI 翻译。

## 7. 验收标准

### 7.1 文章提取

- 在包含标题、作者、正文和图片的典型英文文章页面上，能够提取主要文章内容。
- 导航、广告、推荐内容和评论不出现在最终译文中。
- 正文顺序与原文一致。

### 7.2 Markdown 与图片

- 提取结果为有效 Markdown。
- 原文正文图片均以 `![alt](src)` 形式出现在对应位置。
- 图片地址和链接地址在翻译后保持不变。

### 7.3 翻译与展示

- 英文标题和正文被翻译为中文。
- 翻译内容在浏览器侧边栏中逐步显示，具有可感知的打字机效果。
- 翻译完成后不存在明显的段落重复、缺失或顺序错乱。
- 最终内容符合本文第 5 节规定的格式。

### 7.4 本地持久化

- 首次成功翻译后，关闭并重新打开插件仍可查看该结果。
- 第二次成功翻译后，本地仅保留第二次结果。
- 翻译失败或中断不会覆盖已有的最近一次成功结果。
