# Chrome 英文网页翻译插件技术架构设计文档

## 1. 文档说明

### 1.1 目的

本文依据产品需求文档，定义 Chrome 英文网页翻译插件的总体技术架构、模块职责、关键流程、技术选型、目录结构、编码规范、安全边界与质量保障方案，作为后续开发与评审的统一依据。

### 1.2 文档范围

本文仅描述技术架构及工程规范，不包含具体业务代码、组件代码或可直接运行的实现。

### 1.3 需求基线

- 运行于 Chrome 浏览器。
- 提取当前英文网页的主要文章内容并转换为 Markdown。
- 保留文章标题、作者、原文链接、正文结构及正文图片。
- 通过 OpenAI SDK 兼容接口调用 Qwen 模型进行流式翻译。
- 在浏览器侧边栏中以打字机效果展示翻译结果。
- 使用 React 与 `md-wx` 渲染 Markdown。
- 本地仅持久化最近一次成功翻译结果。

## 2. 架构目标与原则

### 2.1 架构目标

- **提取准确**：优先保证主要文章正文、元数据和图片位置的完整性。
- **结构稳定**：翻译前后保持 Markdown 标题、段落、列表、引用、代码、链接和图片结构稳定。
- **流式可见**：模型响应到达后及时呈现，避免等待整篇翻译完成。
- **模型可替换**：业务流程不依赖 Qwen 专有接口，通过 OpenAI 兼容协议切换服务地址和模型。
- **权限最小化**：只申请完成当前页面提取、侧边栏展示、本地存储和模型请求所需权限。
- **职责隔离**：网页提取、翻译编排、状态管理、持久化和视图渲染相互解耦。
- **可验证**：关键转换过程使用稳定的数据契约，并针对提取、Markdown 和流式拼接建立测试基线。

### 2.2 设计原则

- 使用已渲染的当前页面 DOM，不重复抓取网页 URL。
- 在页面上下文内完成正文识别，扩展上下文只接收结构化提取结果。
- 先完成内容提取和规范化，再调用模型，避免将整页噪声发送给模型。
- 翻译过程只追加已确认的增量内容，完整成功后再覆盖本地最近一次结果。
- API Key 不进入仓库、日志、错误消息或文章持久化数据。
- 对外部依赖建立适配层，避免第三方 SDK 或组件类型扩散到核心领域层。

## 4. 内容提取方案调研与决策

### 4.1 候选方案

#### 方案 A：仅使用 Mozilla Readability

Readability 是 Firefox Reader View 使用的正文提取器，可从 DOM 中返回标题、正文 HTML、纯文本、作者、语言、站点名等数据。其优点是成熟、稳定、无服务依赖、浏览器端可运行；不足是对复杂技术文档、代码、数学公式、脚注和非典型文章布局可能清理过度。

#### 方案 B：Defuddle 单引擎

Defuddle 源于 Obsidian Web Clipper，面向网页剪藏场景。它比 Readability 更保守，并强化了代码块、表格、脚注、数学内容和 Schema.org 元数据处理。其输出与本项目“文章转 Markdown 后交给 LLM”的目标更吻合。不足是项目仍明确标注为持续演进中，稳定性历史短于 Readability。

#### 方案 C：Defuddle 主引擎 + Readability 质量回退

默认使用 Defuddle 提取；当结果为空、正文长度不足、正文链接密度异常、标题缺失且无法从页面元数据补齐，或提取过程异常时，使用 Readability 对页面克隆再次解析。两个结果经过统一质量评估，选择分数更高者，再进入 URL 规范化与 Markdown 转换。

### 4.2 最终决策

采用**方案 C：Defuddle 主引擎 + Readability 质量回退 + Turndown 统一转换**。

选择原因：

1. Defuddle 更适合文章剪藏及 LLM 输入，能更好保留技术文章常见结构。
2. Readability 有长期实践基础，可降低单一新提取器带来的兼容风险。
3. 两个提取器都在当前页面已渲染 DOM 上运行，不需要额外网页抓取服务。
4. 统一输出为内部文章模型，后续流程不感知具体提取器。
5. Turndown 负责最终 Markdown 规则，避免不同提取器直接输出造成格式不一致。

### 4.3 提取处理链

1. 验证当前标签页是否允许注入及是否存在可见正文。
2. 克隆页面 DOM，禁止提取器修改用户正在浏览的原页面。
3. 在克隆 DOM 中移除脚本、样式、表单、对话框及确定为非正文的节点。
4. 规范化延迟加载图片，优先选择已解析的真实图片地址。
5. 运行 Defuddle，获取正文、标题、作者和页面元数据。
6. 对结果执行质量评分；低于阈值或解析失败时运行 Readability。
7. 比较候选结果，选择质量更高的文章正文。
8. 将正文内相对链接和图片地址转换为基于原文 URL 的绝对地址。
9. 使用 Turndown 转换为统一 Markdown，并应用 GFM 规则。
10. 对 Markdown 执行结构校验，生成标准化文章对象。

### 4.4 提取质量评估

质量评估不依赖单一字符阈值，应综合以下信号：

- 正文是否存在且达到最低有效长度；
- 标题是否存在，或能否从 Open Graph、JSON-LD、页面标题中补齐；
- 正文段落数量与平均长度是否合理；
- 文本与链接比例是否符合文章特征；
- 导航、登录、订阅、评论和推荐词汇是否异常密集；
- 图片、标题、列表和代码块是否位于正文合理位置；
- 提取结果是否包含大量重复段落；
- 输出是否包含脚本、样式或不可见控件文本。

质量评估输出统一分数、命中规则和所选提取器标识，供诊断使用；诊断信息不得进入最终译文。

### 4.5 图片处理规则

- 图片在提取 DOM 中的位置必须保留。
- 优先使用浏览器已解析的绝对图片地址。
- 对延迟加载图片，依次评估实际 `src`、候选资源集合及常见延迟加载属性，排除占位图。
- 图片替代文本优先使用原始 `alt`；没有时允许为空。
- Markdown 统一输出为 `![alt](src)`。
- 不下载、不转存、不转为 Base64，不对图片内容调用视觉模型。
- 不把页面装饰图、头像、图标、跟踪像素和明显广告图纳入正文。

### 4.6 动态页面边界

内容脚本读取用户触发翻译时已经渲染的 DOM，因此可覆盖多数客户端渲染页面。尚未加载的无限滚动内容、跨域 iframe、Shadow DOM 深层私有内容、付费墙后内容及浏览器受限页面不保证提取。首期不通过自动滚动或模拟用户操作扩大页面内容范围。

## 5. 总体架构

系统分为五个运行边界：

1. **页面内容脚本**：访问当前页面 DOM，执行内容提取、图片和 URL 规范化、Markdown 转换。
2. **后台 Service Worker**：负责插件命令协调、侧边栏开启、消息路由和受限页面判断，不保存长时运行状态。
3. **侧边栏 React 应用**：承载用户交互、流程状态、流式译文拼接和 `md-wx` 渲染。
4. **AI 适配层**：封装 OpenAI SDK 兼容调用、Qwen 配置、流读取、取消、超时与错误归一化。
5. **本地存储层**：保存最近一次成功译文及必要配置，提供版本化数据契约。

### 5.1 模块职责

| 模块 | 核心职责 | 禁止承担的职责 |
|---|---|---|
| Content Extractor | 读取和清洗页面、选择正文、生成 Markdown | 调用 AI、控制 UI、写持久化结果 |
| Background Coordinator | 打开侧边栏、路由一次性消息、检查标签页 | 维护流式翻译正文、执行 DOM 提取细节 |
| Translation Orchestrator | 组装翻译输入、控制请求生命周期、拼接增量 | 直接访问页面 DOM、直接渲染组件 |
| OpenAI-compatible Adapter | 对接 SDK、转换流事件、归一化服务错误 | 决定 UI 状态、处理文章提取 |
| Side Panel UI | 显示状态、译文和错误，接收用户操作 | 持有供应商专有协议逻辑 |
| Markdown Presenter | 将当前完整 Markdown 交给 `md-wx` | 修改译文语义或修复模型输出 |
| Result Repository | 读写最近一次成功结果 | 保存翻译历史或未完成草稿 |

### 5.2 数据流

1. 用户从插件入口发起翻译。
2. 后台协调器打开侧边栏，并向当前标签页请求提取。
3. 内容脚本返回标准化文章对象，其中正文已经是 Markdown。
4. 侧边栏将状态切换为“正在翻译”，翻译编排器生成固定格式的模型输入。
5. AI 适配层通过 OpenAI 兼容 Chat Completions 接口请求 Qwen 流式响应。
6. 每个有效文本增量被追加到内存缓冲区，并触发节流后的 React 更新。
7. `md-wx` 使用当前完整 Markdown 缓冲区重新渲染可见内容，形成打字机效果。
8. 流正常结束后执行格式和完整性校验。
9. 校验通过后，以原子覆盖方式保存最近一次成功结果。
10. 失败或中止时保留当前界面错误状态，但不覆盖已存成功结果。

## 6. 内部数据契约

### 6.1 提取文章对象

提取层统一返回以下语义字段：

- 数据契约版本；
- 原始页面 URL；
- 原始标题；
- 作者；
- 页面语言；
- 站点名称；
- Markdown 正文；
- 正文字数或字符数；
- 使用的提取器；
- 提取质量分数；
- 提取时间。

业务层只能依赖该统一对象，不能直接依赖 Defuddle 或 Readability 的原始返回类型。

### 6.2 翻译会话状态

翻译流程采用显式状态机：

- `idle`：等待操作；
- `extracting`：正在提取页面；
- `translating`：正在接收模型输出；
- `completed`：完整翻译并已持久化；
- `failed`：提取、请求或校验失败；
- `cancelled`：用户主动终止。

状态只允许按定义路径迁移，避免并发点击造成旧请求覆盖新请求。

### 6.3 最近一次成功结果

本地结果包含：

- 存储结构版本；
- 原文 URL；
- 标题；
- 作者；
- 完整翻译 Markdown；
- 完成时间；
- 模型标识。

不保存原始完整 HTML、提取 DOM、流式中间片段、API Key、调试日志或多条历史结果。

## 7. AI 翻译架构

### 7.1 协议选择

采用 OpenAI JavaScript SDK 的 Chat Completions 兼容接口。模型连接配置抽象为：

- API Base URL；
- API Key；
- 模型名称；
- 请求超时；
- 最大重试次数；
- 可选的兼容参数。

Qwen Model Studio 提供 OpenAI 兼容接口，切换时只需调整服务地址、API Key 和模型名。核心翻译流程不引用 Qwen 专有返回类型。

### 7.2 Qwen 使用约束

- 默认使用 Qwen 文本模型，具体型号由配置确定。
- 使用流式 Chat Completions 满足动态展示需求。
- 默认关闭与翻译无关的搜索、工具调用和代码执行能力。
- 翻译任务不需要深度推理内容，避免将推理增量混入最终 Markdown。
- 仅消费最终文本增量，忽略空事件和供应商扩展事件。
- Qwen 专有参数必须留在供应商配置边界内，不得扩散到翻译领域层。

### 7.3 翻译输入与输出约束

模型输入由固定系统约束、文章元数据和 Markdown 正文组成。模型必须：

- 只输出最终 Markdown，不输出解释或代码围栏；
- 翻译标题和正文，保留作者名；
- 保持链接目标、图片地址、代码块内容及 Markdown 结构；
- 按需求规定的标题、作者、原文链接、正文顺序输出；
- 不遗漏正文，不添加原文不存在的事实。

### 7.4 长文章策略

首选在模型上下文限制内单次翻译，以获得最佳上下文连贯性。当输入超过配置的安全阈值时，按 Markdown 块边界切分，禁止按任意字符截断。切分优先级为二级标题、段落、列表或完整代码块，并保持图片与相邻段落关系。

多段翻译时：

- 标题和元数据只生成一次；
- 各段携带必要的前文摘要或术语上下文；
- 按原始序号串行合并，禁止并行响应乱序；
- 最终统一执行结构校验后才持久化；
- 任一分段失败即视为整篇未完成。

### 7.5 流式拼接与打字机效果

模型流是内容来源，打字机效果是显示策略，两者分离：

- AI 适配层持续产生文本增量；
- 翻译编排器将增量追加到单一 Markdown 缓冲区；
- UI 按固定短间隔批量刷新，避免每个字符都触发 React 与 Markdown 全量渲染；
- 流结束后立即刷新剩余缓冲并进入校验；
- 新请求启动或用户取消时，前一请求的后续增量必须失效。

## 8. md-wx 呈现方案

### 8.1 依赖状态

`md-wx` 已通过 npm 安装，当前依赖范围为 `^1.0.1`。项目使用其 `MarkdownRenderer` 作为最终译文的 Markdown 展示边界，并加载包提供的样式资源。

### 8.2 组件使用原则

- `markdown` 数据源始终为翻译缓冲区的完整快照。
- 侧边栏首期采用适合窄视口的阅读布局。
- 首期关闭与核心翻译无关的设置面板、视图切换和复杂编辑能力。
- 主题能力可保留为呈现层配置，但不得影响翻译数据。
- 复制能力是否开放服从产品后续决策，不进入核心流程。
- `md-wx` 仅负责渲染，不作为 Markdown 生成、清洗或校验工具。

### 8.3 安全与兼容约束

- 只向组件传递由内部流程生成的 Markdown，不传递原始网页 HTML。
- 外部链接点击行为、图片加载和潜在原始 HTML 渲染能力需在安全评审中验证。
- 对流式未闭合的 Markdown 语法允许暂时降级显示，流结束后必须恢复为有效结构。
- 当 `md-wx` 升级时，应回归图片、链接、引用、列表、代码块和流式未闭合语法场景。

## 9. Chrome 扩展架构约束

### 9.1 Manifest V3

- 后台使用 Service Worker，不假设其持续存活。
- 长时流式翻译由侧边栏页面负责，避免依赖可能被回收的后台进程。
- 后台只承担短生命周期协调工作。
- 扩展打包产物不得从远程加载可执行代码。

### 9.2 权限原则

建议仅申请：

- 当前活动标签页访问权限；
- 按用户动作注入内容脚本的权限；
- 侧边栏权限；
- 本地存储权限；
- AI 服务域名对应的网络访问权限。

不申请与需求无关的浏览历史、下载、书签、所有标签页常驻读取等权限。若允许用户自定义任意 OpenAI 兼容地址，主机权限策略必须单独评审，不能默认开放全部网络地址。

### 9.3 消息通信

- 所有跨上下文消息使用可辨识的消息类型和版本化载荷。
- 请求必须带唯一请求标识，以隔离重复点击、页面切换和过期响应。
- 内容脚本只响应当前页面提取请求，不接收模型密钥。
- 错误通过统一错误码传递，不直接跨边界传递第三方异常对象。

## 10. 本地持久化设计

### 10.1 存储分区

- **配置区**：模型服务地址、模型名及用户授权后的密钥。
- **结果区**：最近一次成功翻译结果。
- **偏好区**：必要的显示偏好；首期保持最小化。

### 10.2 写入策略

- 翻译过程中只保存在内存中。
- 完整流结束且结构校验通过后写入临时对象，再以单次覆盖更新最近结果。
- 写入失败时当前翻译仍可展示，但状态应明确提示未能持久化。
- 新成功结果覆盖旧结果，不追加数组，不建立索引。

### 10.3 密钥约束

浏览器扩展无法像后端服务一样完全隐藏用户 API Key。若由用户配置密钥，应明确其保存在本地扩展存储并只用于目标模型服务。不得把密钥写入源码、构建变量、日志、URL 参数、消息广播或翻译结果。若未来需要平台统一密钥，必须改为受控后端代理，不应将平台密钥打包进扩展。

### 11.1 目录规则

- 每个运行上下文拥有独立入口目录，不跨目录直接访问浏览器上下文对象。
- `shared` 只放置真正跨模块复用的契约、错误和常量，不放业务杂项工具。
- 提取器通过统一接口接入，提取器原始类型不得离开 `extractors`。
- AI 服务商差异限制在 `translation/providers`。
- 存储读写必须经过 repository，不允许 UI 直接调用 Chrome Storage。
- 单元测试优先与被测模块同目录或使用统一命名；浏览器级测试集中放在 `tests`。
- 文件名使用 kebab-case；React 组件文件可使用 PascalCase。
- 禁止建立含义模糊的 `utils.ts`、`helpers.ts` 或超大型公共模块。

## 12. 编码规范

### 12.1 TypeScript

- 全项目启用严格类型检查。
- 禁止无理由使用 `any`；外部输入先视为 `unknown` 并在边界完成校验。
- 领域对象、消息载荷和存储结构必须有明确类型及版本。
- 使用可辨识联合类型表达流程状态和消息类型。
- 函数应有单一职责，复杂分支拆分到命名明确的领域函数。
- 对可能失败的边界操作使用统一结果或领域错误，不用字符串匹配判断错误类型。

### 12.2 命名

- 类型、接口、React 组件使用 PascalCase。
- 变量、函数、Hook 使用 camelCase。
- 常量使用 UPPER_SNAKE_CASE，仅用于真正不变的全局常量。
- 文件与目录默认使用 kebab-case。
- 布尔值以 `is`、`has`、`can`、`should` 开头。
- 事件处理函数以 `handle` 开头，组件回调属性以 `on` 开头。
- 名称表达业务含义，禁止 `data`、`info`、`temp` 等缺少上下文的泛化名称。

### 12.3 React

- 采用函数组件和 Hook。
- 组件只负责展示和用户交互，提取、翻译与存储逻辑放入独立模块或 Hook。
- 派生状态通过现有状态计算，不重复存储。
- 流式更新采用批量刷新，避免逐字符触发昂贵渲染。
- 副作用必须声明清理行为，特别是流式请求、计时器和消息监听。
- 禁止在渲染过程中访问 Chrome API 或发起网络请求。

### 12.4 异步与错误处理

- 所有长时操作支持取消信号。
- 每个外部边界设定明确超时，不创建无限等待。
- 捕获异常后转换为领域错误码，并保留可诊断但不含敏感信息的原因。
- 不空捕获异常，不用控制台日志替代用户状态和错误处理。
- 新请求开始时取消旧请求；旧请求返回时必须根据请求标识丢弃。

### 12.5 格式与提交质量

- 使用 ESLint 负责代码质量规则，Prettier 负责格式。
- 统一 UTF-8、LF、两空格缩进和文件末尾换行。
- 导入按外部依赖、内部绝对路径、相对路径分组。
- 禁止提交密钥、真实用户文章、构建产物和临时调试文件。
- 新增行为必须配套相应层级测试，不以人工浏览作为唯一验证。

### 12.6 注释与文档

- 注释解释设计原因、边界或不可见约束，不重复代码表面含义。
- 对提取质量规则、模型输出约束和跨上下文消息契约保留必要说明。
- 公共契约发生不兼容变化时同步更新架构文档和存储版本。

## 13. 安全与隐私设计

- 只在用户明确触发后读取当前活动页面。
- 内容脚本不接收 API Key，页面脚本无法访问扩展内部配置。
- 发送给模型的内容仅包含标题、作者、原文链接和已提取正文。
- 提取前移除表单字段、隐藏控件、脚本和非正文页面数据。
- 日志不得记录完整文章、API Key、授权头或完整模型响应。
- Markdown 渲染边界必须防止脚本、事件属性及危险 URL 执行。
- 外部图片可能向原站发起请求，需在隐私说明中告知用户。
- 扩展内容安全策略遵循 Manifest V3，不允许远程脚本和动态执行字符串。

## 14. 错误模型与恢复策略

| 错误类别 | 示例 | 用户表现 | 数据处理 |
|---|---|---|---|
| 页面受限 | Chrome 内部页、扩展页 | 提示当前页面不支持 | 不发起提取 |
| 提取失败 | 无正文、两个提取器均低质量 | 提示无法识别主要文章 | 不调用模型 |
| 内容过长 | 超出可接受切分范围 | 提示文章超过当前限制 | 不覆盖旧结果 |
| 配置错误 | 缺少密钥、地址或模型名 | 引导完成配置 | 不发送正文 |
| 网络错误 | 断网、超时 | 显示可重试错误 | 保留旧结果 |
| 服务错误 | 鉴权、限流、模型不可用 | 显示归一化错误信息 | 不覆盖旧结果 |
| 流中断 | 响应中途断开 | 标记翻译未完成 | 部分内容不持久化 |
| 输出非法 | 格式缺失、结构破坏 | 提示结果校验失败 | 不持久化 |
| 存储失败 | 配额或浏览器异常 | 译文可读但提示未保存 | 旧结果保持不变 |

重试仅适用于临时网络错误、限流和部分服务端错误；鉴权失败、内容无效和页面受限不得自动重试。自动重试次数应有限，并服从取消信号。

## 15. 性能设计

- 页面解析在克隆 DOM 上执行，并设置可接受的节点规模上限。
- 确定无关节点在进入提取器前删除，降低评分和转换成本。
- 只传输清洗后的文章对象，不跨上下文传输完整 DOM 或整页 HTML。
- Markdown 增量进入缓冲区后节流渲染，避免 `md-wx` 高频全量解析。
- 侧边栏只保存当前会话与最近结果，不在内存维护历史列表。
- 长文章切分以结构边界为单位，减少重复上下文和模型调用次数。
- 提取耗时、首个翻译增量耗时、总翻译耗时仅记录匿名数值，不记录正文。

## 16. 测试策略

### 16.1 内容提取测试

建立脱敏 HTML 固件集，至少覆盖：

- 标准新闻文章；
- 技术博客及多级标题；
- 含列表、引用、表格和代码块的教程；
- 含普通图片、相对地址、`srcset` 和延迟加载图片的文章；
- 包含广告、导航、推荐、评论和订阅弹窗的页面；
- 客户端渲染后的页面快照；
- 无正文页面与正文过短页面；
- Defuddle 失败并触发 Readability 回退的页面。

断言标题、作者、正文关键段落、噪声排除、图片位置、绝对 URL 和提取器选择。

### 16.2 Markdown 测试

- 图片严格符合 `![alt](src)`；
- 链接和图片地址保持不变；
- 标题、列表、引用、表格和代码块结构有效；
- 脚本、样式和控件文本不进入输出；
- 重复转换结果稳定；
- 最终文档格式符合需求模板。

### 16.3 翻译测试

AI 适配层使用模拟流，不在单元测试中调用真实付费模型。覆盖：

- 正常增量、空增量和多字节中文增量；
- 正常完成、超时、限流、鉴权失败和流中断；
- 取消旧请求及忽略过期事件；
- 长文章串行分段与顺序合并；
- 失败时不覆盖最近成功结果；
- 图片、链接和代码块在翻译后保持完整。

真实 Qwen 连接作为受控集成测试，使用专用测试密钥和短文本，不进入默认测试流程。

### 16.4 UI 与 E2E 测试

- 侧边栏各状态正确迁移；
- 流式内容持续出现且无重复；
- `md-wx` 正确渲染标题、引用、图片、链接和代码；
- 关闭并重开侧边栏后显示最近一次成功结果；
- 在真实扩展环境验证权限、注入、消息、网络和本地存储流程。

| 编号 | 决策 | 结论 |
|---|---|---|

| ADR-006 | 持久化 | Chrome Storage Local 仅保存最近一次完整成功结果 |
| ADR-007 | 长文章 | 按 Markdown 结构串行切分，整篇成功后统一保存 |

## 18. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| Defuddle 仍在快速演进 | 升级后提取结果变化 | 锁定版本、建立固件回归、保留 Readability 回退 |
| 两个提取器均误判 | 翻译噪声或正文缺失 | 质量评分、最低阈值、明确失败而非强行翻译 |
| 模型破坏 Markdown | 图片或链接失效 | 强提示约束、输出校验、结构固件测试 |
| 流式高频渲染 | 侧边栏卡顿 | 增量缓冲与节流刷新 |
| Service Worker 被回收 | 长任务中断 | 长流任务放在侧边栏，后台无关键会话状态 |
| 用户密钥暴露 | 安全与费用风险 | 最小传递、本地隔离、不记录、不注入页面 |
| 自定义 Base URL 扩大权限 | 商店审核与安全风险 | 首期限定受信服务域名或采用显式授权策略 |
| 图片防盗链或失效 | 译文图片不可见 | 保留原 URL、展示失败提示、不承诺转存 |
| 本地存储配额 | 长文无法保存 | 保存 Markdown 而非 HTML/DOM，写入前检查大小 |

## 19. 实施边界

本架构文档不决定以下事项，进入实现计划前应单独确认：

- 具体 Chrome 扩展构建插件及版本；
- Defuddle、Readability、Turndown 和 OpenAI SDK 的锁定版本；
- Qwen 默认模型名称、区域和 Base URL；
- API Key 的用户配置界面；
- 长文章安全阈值和最大分段数量；
- 是否开放 `md-wx` 主题、复制和视图切换能力；
- 是否允许用户配置任意 OpenAI 兼容服务地址。
