# 侧边栏主页面设计与实现规划

## 1. 页面定位

侧边栏是插件的核心页面，承担当前网页的一键翻译、过程反馈、译文阅读、失败恢复和 Markdown 下载。页面不提供历史列表、编辑器、主题切换、语言选择等非核心功能。

## 2. 页面模块

| 模块 | 功能 | 显示时机 |
|---|---|---|
| 顶部栏 | 展示产品名称，进入设置页 | 始终显示 |
| 当前网页摘要 | 展示当前标签页标题和域名 | 空闲、失败、完成状态 |
| 主操作区 | 一键翻译、取消或重新翻译 | 随状态变化 |
| 状态反馈区 | 展示提取、翻译、完成或错误状态 | 非空闲状态 |
| 译文阅读区 | 使用 `md-wx` 流式渲染 Markdown | 翻译中、完成状态 |
| 底部操作区 | 下载 Markdown | 完成状态 |

## 3. 页面状态与 ASCII 布局

### 3.1 空闲状态

用户打开侧边栏后首先看到当前网页和唯一的主操作按钮。若存在上一次成功结果，可在当前网页摘要下方恢复展示，但“一键翻译当前网页”仍是主要操作。

```text
+--------------------------------------+
| 网页翻译                         [设置] |
+--------------------------------------+
|                                      |
| 当前网页                              |
| ------------------------------------ |
| How to Build Reliable AI Systems     |
| example.com                          |
|                                      |
| +----------------------------------+ |
| |          一键翻译当前网页          | |
| +----------------------------------+ |
|                                      |
| 提取正文并翻译为中文，结果仅保存在本地。 |
|                                      |
+--------------------------------------+
```

交互规则：

- 主按钮使用页面中最高视觉权重。
- 点击后立即进入“正在提取”状态，防止重复触发。
- 当前页面不受支持时，按钮禁用，并在按钮下方说明原因。
- 模型配置不完整时，点击主按钮后引导进入设置页，不发送网页正文。

### 3.2 提取与翻译状态

提取阶段显示明确状态；收到第一个模型增量后进入翻译阶段。正文区域随流增量更新，不显示百分比或虚假剩余时间。

```text
+--------------------------------------+
| 网页翻译                         [设置] |
+--------------------------------------+
| [●] 正在翻译                         |
| How to Build Reliable AI Systems     |
|                                      |
| +----------------------------------+ |
| | # 如何构建可靠的 AI 系统           | |
| |                                  | |
| | > **作者**：Jane Doe              | |
| | > **原文链接**：example.com/...   | |
| |                                  | |
| | 可靠的 AI 系统需要清晰的边界、可观 | |
| | 测性以及可重复的验证流程……         | |
| |                                  | |
| | [Markdown 内容持续追加]            | |
| +----------------------------------+ |
|                                      |
|              [取消翻译]              |
+--------------------------------------+
```

交互规则：

- 状态文案依次为“正在提取文章”和“正在翻译”。
- `md-wx` 接收当前完整 Markdown 快照，并按节流频率刷新。
- 已展示内容保持稳定，不重复、不回退。
- 点击“取消翻译”终止当前请求，部分译文不写入本地结果。
- 页面切换或新请求开始后，旧请求增量失效。

### 3.3 完成状态

完成后将下载作为主要结果操作，同时保留重新翻译入口。

```text
+--------------------------------------+
| 网页翻译                         [设置] |
+--------------------------------------+
| [√] 翻译完成                         |
|                                      |
| +----------------------------------+ |
| | # 如何构建可靠的 AI 系统           | |
| |                                  | |
| | > **作者**：Jane Doe              | |
| | > **原文链接**：example.com/...   | |
| |                                  | |
| | [完整 Markdown 译文，由 md-wx 渲染] | |
| |                                  | |
| | ![架构示意图](https://.../a.png)  | |
| +----------------------------------+ |
|                                      |
| +----------------------------------+ |
| |          下载 Markdown            | |
| +----------------------------------+ |
|             [重新翻译]               |
+--------------------------------------+
```

交互规则：

- 成功完成并通过结构校验后，覆盖本地最近一次成功结果。
- “下载 Markdown”下载当前完整译文，扩展名为 `.md`。
- 文件名优先使用净化后的译文标题；标题不可用时使用 `translated-article.md`。
- 下载内容严格包含标题、作者、原文链接和译文正文，不混入状态信息。
- “重新翻译”重新提取当前活动页面，不复用旧页面正文。

### 3.4 失败或取消状态

```text
+--------------------------------------+
| 网页翻译                         [设置] |
+--------------------------------------+
| [!] 翻译未完成                       |
|                                      |
| 无法连接模型服务，请检查网络或模型配置。 |
|                                      |
| +----------------------------------+ |
| |              重试                | |
| +----------------------------------+ |
|             [打开设置]               |
|                                      |
| 上一次成功结果未被覆盖。              |
+--------------------------------------+
```

交互规则：

- 错误文案面向用户，不展示异常堆栈、授权头或第三方原始响应。
- 临时网络错误提供“重试”；配置错误提供“打开设置”。
- 提取失败不调用模型。
- 失败和取消均不覆盖最近一次成功结果。

## 4. 页面流程

```text
打开侧边栏
    |
    v
读取当前标签页 + 最近成功结果
    |
    v
点击“一键翻译当前网页”
    |
    +--> 配置缺失 ------> 设置页面
    |
    v
请求内容脚本提取文章
    |
    +--> 提取失败 ------> 失败状态
    |
    v
发起 Qwen 流式翻译
    |
    +--> 用户取消 ------> 取消状态
    +--> 请求失败 ------> 失败状态
    |
    v
增量缓冲 + md-wx 节流渲染
    |
    v
输出结构校验
    |
    +--> 校验失败 ------> 失败状态
    |
    v
保存最近成功结果
    |
    v
完成状态 --> 下载 Markdown
```

## 5. 功能模块实现步骤

### 阶段 1：页面基础与状态骨架

1. 建立 Side Panel React 入口及窄视口基础样式。
2. 定义 `idle`、`extracting`、`translating`、`completed`、`failed`、`cancelled` 状态。
3. 建立顶部栏、网页摘要、主操作区、状态反馈区、译文区和底部操作区。
4. 根据状态控制模块显示、按钮文案与可用性。
5. 验证侧边栏重开后可恢复最近一次成功结果。

### 阶段 2：当前网页与正文提取

1. 读取当前活动标签页，判断是否为允许处理的网页。
2. 为每次操作生成唯一请求标识。
3. 向 Content Script 发送提取请求。
4. 接收标准化文章对象，不接收完整 DOM 或整页 HTML。
5. 显示提取失败、受限页面和无有效正文错误。

### 阶段 3：流式翻译与展示

1. 校验模型设置完整性。
2. 将文章对象交给翻译编排器，启动支持取消和超时的流式请求。
3. 将有效文本增量追加到单一 Markdown 缓冲区。
4. 按固定短间隔刷新 React 状态，避免逐字符重渲染。
5. 使用 `md-wx` 的 `MarkdownRenderer` 渲染当前完整快照。
6. 请求结束后刷新剩余缓冲并执行输出结构校验。

### 阶段 4：持久化与 Markdown 下载

1. 仅在完整成功后写入最近一次结果。
2. 从完整译文生成 UTF-8 Markdown 文件。
3. 净化标题，移除文件名非法字符并限制长度。
4. 触发浏览器下载，不创建服务端文件或历史记录。
5. 验证图片 Markdown、链接地址、代码块及中文字符在下载后保持完整。

### 阶段 5：错误与并发控制

1. 新请求启动前取消旧请求。
2. 根据请求标识丢弃过期响应。
3. 将提取、配置、网络、鉴权、限流、流中断、校验和存储错误映射为用户文案。
4. 确保失败、取消和未完成结果不覆盖旧结果。
5. 覆盖空闲、提取、翻译、完成、失败、取消和恢复场景测试。

## 6. 验收要点

- 用户最多一次点击即可开始翻译当前网页。
- 翻译中可持续看到新增译文并可取消。
- 完成后可下载 UTF-8 编码的 `.md` 文件。
- 下载内容符合需求规定的标题、作者、原文链接、正文顺序。
- 图片保持 `![alt](src)` 格式和原始正文位置。
- 页面不出现历史、收藏、编辑、主题市场等冗余功能。
- 配置、失败或取消不会覆盖最近一次成功结果。
