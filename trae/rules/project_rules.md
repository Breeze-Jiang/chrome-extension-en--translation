# Chrome 英文网页翻译插件项目规则

## 1. 规则目的

本文是 AI 助手在本项目开发过程中必须遵循的高层规则，用于统一任务范围、技术基线、架构边界、代码质量、安全要求和验收方式。

具体功能、文件范围和验收标准以 `docs/tasks.md` 中用户当前明确指定的任务为准。本规则不授权 AI 自动开始或扩展任何开发任务。

## 2. 规则优先级

发生冲突时按以下顺序处理：

1. 用户当前明确指令；
2. `docs/tasks.md` 中当前指定任务的范围和验收标准；
3. 本项目规则；
4. `docs/desgin.md` 技术架构设计文档；
5. `docs/proposal.md` 产品需求文档；
6. `docs/layout/` 页面布局文档；
7. 现有代码约定和第三方官方文档。

若高优先级指令可能破坏安全边界、核心产品约束或用户数据，必须先说明风险并等待确认。

## 3. AI 助手任务执行规范

### 3.1 任务范围控制

- **严格按照任务拆分执行**：只执行 `docs/tasks.md` 中用户明确指定的任务，不得超出任务边界。
- **单一任务原则**：每次只执行一个任务，例如 `T01` 或 `T02`；完成后停止并等待用户确认。
- **禁止自动扩展**：不得根据架构文档、后续任务或个人判断提前实现其他能力。
- **最小必要变更**：只修改当前任务要求的文件，以及完成该任务所必需的直接配置。
- **禁止顺手重构**：不清理无关代码、不升级无关依赖、不调整无关页面、不重新组织项目。
- **范围变更需确认**：确需修改任务范围外文件或公共接口时，先说明原因、影响和替代方案，等待用户确认。

### 3.2 任务指令格式

推荐用户使用以下格式：

```text
请执行任务 Txx：[任务名称]
只完成任务 Txx 中列出的内容，不要超出范围。
完成后等待我确认再进行下一步。
```

如果用户只说“继续”：

- 当前任务尚未完成：继续当前任务；
- 当前任务已经完成：不得自动开始下一任务，应请用户明确任务编号；
- 无法确认当前任务：询问用户要执行的任务编号。

### 3.3 执行前检查

开始任务前必须：

1. 阅读 `docs/tasks.md` 中当前任务的完整内容；
2. 确认前置依赖是否已完成；
3. 阅读任务引用的需求、架构和页面布局；
4. 阅读将要修改的现有文件，不修改未了解的代码；
5. 明确允许范围、禁止范围、验证方式和可见效果；
6. 避免覆盖用户未提交的工作区变更。

### 3.4 执行过程

- 采用满足当前任务的最小、直接实现，避免过度设计。
- 不使用占位实现、虚假返回或吞掉异常制造完成假象。
- 不通过禁用测试、降低类型检查或扩大忽略规则掩盖问题。
- 发现任务描述不清或与代码现状冲突时，停止推测并向用户确认。
- 未经明确要求，不创建 Git 提交、不推送、不修改 Git 配置。

### 3.5 完成与验收

每个任务完成后必须：

1. 对照任务的实现内容逐项检查；
2. 对照任务的独立验收标准验证；
3. 运行与变更相称的测试、类型检查、Lint 或构建；
4. 检查所有变更均在当前任务范围内；
5. 汇报变更文件、验证结果、可见效果和遗留问题；
6. 停止并等待用户确认，不自动进入下一任务。

若当前环境没有 `finish` 工具，应在最终回复中完成等价总结，不得虚构工具调用。

### 3.6 异常处理

- **描述不清**：先询问具体范围，不自行决定。
- **依赖未完成**：指出缺失任务及影响，等待用户指示。
- **执行受阻**：提供错误证据、已完成部分和可选方案，不机械重复失败操作。
- **需要越界**：先说明必要性并等待确认，不得先改后报。
- **发现范围外代码**：不得擅自删除，应询问是否需要清理。
- **验证失败**：分析是否由当前修改导致，不修改无关行为来迁就测试。

## 4. 产品与技术基线

- 项目是 Chrome 英文网页 AI 翻译扩展。
- 核心链路为：用户触发、提取当前文章、转换 Markdown、调用 Qwen 流式翻译、侧边栏展示、保存最近一次成功结果、下载 Markdown。
- 扩展采用 Chrome Extension Manifest V3。
- UI 使用 React、TypeScript、函数组件和 Hooks。
- 构建使用 Vite 和兼容 Manifest V3 的扩展构建方案。
- Markdown 展示统一使用 `md-wx`。
- 内容提取使用 Defuddle，质量不足时回退 Mozilla Readability。
- HTML 转 Markdown 使用 Turndown 和 GFM 插件。
- AI 调用使用 OpenAI JavaScript SDK 兼容接口，目标模型为 Qwen。
- 本地数据使用 Chrome Storage Local，并通过 Repository 访问。
- 不实现翻译历史、账户、同步、收藏、批量抓取或其他未列入当前任务的功能。

## 5. 架构职责边界

### 5.1 Background Service Worker

- 只负责打开侧边栏、标签页策略、短消息路由和扩展协调。
- 不维护长时流式会话或关键内存状态。
- 不实现正文提取和 UI 渲染。

### 5.2 Content Script

- 只负责当前页面 DOM 提取、URL 与图片规范化和 Markdown 转换。
- 不接收 API Key，不调用模型，不写翻译结果存储。
- 不修改用户正在浏览的原始 DOM，提取应基于克隆内容。

### 5.3 Side Panel

- 负责用户交互、翻译状态、流式缓冲和 Markdown 展示。
- 长时流式任务由侧边栏持有，不依赖 Service Worker 持续存活。
- UI 组件不直接包含提取器、供应商协议或存储实现。

### 5.4 Translation

- 编排器负责输入组装、请求生命周期、流拼接、取消和结果校验。
- OpenAI-compatible 适配器封装 SDK 和 Qwen 差异。
- Prompt、长文分段、输出校验和供应商调用保持职责分离。

### 5.5 Storage 与 Shared

- Chrome Storage 读写统一经过 Repository。
- 配置和最近结果使用独立、版本化的数据契约。
- `shared` 只存放跨模块契约、消息、领域错误和稳定常量。
- 第三方 SDK 类型不得扩散到核心领域契约。

## 6. 项目目录规范

```text
src/
├─ background/    # Service Worker 与标签页协调
├─ content/       # 页面提取、规范化、Markdown 转换
├─ sidepanel/     # 侧边栏 React 页面
├─ options/       # 模型设置 React 页面
├─ translation/   # 翻译编排与模型适配
├─ storage/       # 配置与结果 Repository
├─ shared/        # 跨模块契约、消息、错误、常量
└─ test/          # 共享测试配置与脱敏固件

tests/
├─ integration/   # 跨模块集成测试
└─ e2e/           # 真实扩展流程测试
```

目录原则：

- 每个文件只承担一个清晰职责。
- 文件和目录默认使用 kebab-case；React 组件文件可使用 PascalCase。
- 只有真正跨模块复用的内容才能进入 `shared`。
- 禁止创建含义模糊的 `utils.ts`、`helpers.ts`、`common.ts` 或大型聚合文件。
- 不为一次性逻辑建立抽象，也不为假设的未来需求提前创建目录。
- 优先修改已有文件，只有当前任务确有新职责时才创建文件。

## 7. TypeScript 与代码风格

- 全项目启用 TypeScript 严格模式。
- 禁止无理由使用 `any`、非空断言和不安全类型断言。
- 外部输入、存储数据、消息和第三方响应先视为 `unknown`，在边界校验。
- 状态、消息和可失败结果优先使用可辨识联合类型。
- 类型、接口和 React 组件使用 PascalCase。
- 变量、函数和 Hook 使用 camelCase；Hook 以 `use` 开头。
- 全局常量使用 UPPER_SNAKE_CASE。
- 布尔变量使用 `is`、`has`、`can` 或 `should` 前缀。
- 事件处理函数使用 `handle` 前缀，组件回调属性使用 `on` 前缀。
- 使用 ESLint 约束质量，Prettier 统一格式。
- 统一 UTF-8、LF、两空格缩进和文件末尾换行。
- 函数与组件保持单一职责，优先清晰的直接实现。
- 注释解释原因和边界，不重复代码表面含义。

## 8. React 与页面规范

- 只使用函数组件和 Hooks。
- 组件负责展示与交互；提取、翻译、存储和 Chrome API 调用放在边界模块或专用 Hook。
- 不在渲染阶段访问 Chrome API、操作存储或发起网络请求。
- 请求、流、计时器和消息监听必须具备清理逻辑。
- 流式内容进入单一缓冲区，并节流刷新 React，避免逐字符触发 `md-wx` 全量渲染。
- 页面遵循 `docs/layout/`，保持窄侧边栏优先和简约视觉层级。
- 不擅自启用 `md-wx` 中与核心翻译无关的复杂能力。

## 9. npm 与依赖管理

- 统一使用 npm，不混用 yarn、pnpm 或其他锁文件。
- 依赖变更必须同步更新 `package.json` 和 `package-lock.json`。
- 只添加当前任务直接需要的依赖，不主动升级无关依赖。
- 不引入功能重复的库。
- 新依赖需检查浏览器兼容性、Manifest V3/CSP 兼容性、维护状态、许可证和包体积。
- 正确区分生产依赖和开发依赖。
- 不使用全局安装作为项目运行前提。
- 禁止从 CDN 或远程地址加载可执行 JavaScript，所有执行代码必须随扩展打包。

## 10. 数据、消息与状态

- 跨上下文消息使用明确类型、版本和唯一请求 ID。
- 不跨上下文发送 DOM、整页 HTML、第三方异常对象或 API Key。
- 新请求开始时取消旧请求；无法取消的旧响应按请求 ID 丢弃。
- 翻译状态限定为 `idle`、`extracting`、`translating`、`completed`、`failed`、`cancelled`。
- 流式内容只保存在当前会话内存缓冲区。
- 只有完整流结束并通过校验后才能覆盖最近一次成功结果。
- 失败、取消、中断和非法输出不得覆盖旧结果。

## 11. 内容提取、Markdown 与翻译

- 使用用户触发时已渲染的当前页面 DOM，不重复抓取页面 URL。
- 在克隆 DOM 上提取并移除脚本、样式、表单和明确噪声。
- 默认使用 Defuddle，质量不足时回退 Readability。
- 相对链接和图片地址转换为绝对地址。
- 图片保持原文位置并严格输出为 `![alt](src)`。
- 不下载、不转存、不 Base64 化或翻译图片。
- 业务层只依赖 OpenAI-compatible Provider，不依赖 Qwen 专有类型。
- Base URL、API Key 和模型名来自配置 Repository，不写入源码。
- 模型只输出最终 Markdown，不输出解释、代码围栏或推理内容。
- 保持作者、原文 URL、图片 URL、链接目标和代码内容不变。
- 长文章按 Markdown 结构边界串行切分，不任意截断、不并行乱序合并。
- 任一分段失败即视为整篇未完成。

## 12. 安全与隐私

- 仅在用户明确触发后读取当前活动页面。
- 发送给模型的内容仅限标题、作者、原文链接和已清洗正文。
- API Key 不得进入源码、构建变量、日志、URL、页面消息、错误信息、测试快照或翻译结果。
- Content Script 不得接收 API Key。
- Manifest 权限遵循最小化原则，不为开发便利申请无关权限。
- Markdown 渲染必须阻止脚本、事件属性和危险 URL 执行。
- 不记录完整文章、完整模型响应或可还原用户阅读内容的日志。
- 测试固件必须脱敏，不提交真实文章或真实密钥。
- 不绕过登录、付费墙、验证码或浏览器访问限制。

## 13. 错误处理与验证

- 外部错误统一转换为领域错误码，不向用户展示堆栈、敏感信息或第三方原始响应。
- 页面受限或无有效正文时不调用模型。
- 临时网络错误和限流可有限重试；鉴权失败、配置无效和输出非法不自动重试。
- 不空捕获异常，不以控制台日志代替状态管理和用户反馈。
- 新行为必须有与风险相称的测试。
- 纯逻辑使用单元测试，React 行为使用组件测试，跨模块流程使用集成测试，真实扩展上下文使用 E2E。
- AI 单元测试使用模拟流，不默认调用真实付费模型。
- 不修改或删除有效测试来迁就错误实现。

## 14. 文件与版本控制

- 不主动创建额外 README、设计文档、示例或与任务无关的文件。
- 不提交 `.env`、密钥、日志、构建产物或临时调试文件。
- 不执行破坏性 Git 操作，不覆盖用户未提交变更。
- 未经明确要求，不提交、不推送、不变基、不修改 Git 配置。
- 删除文件前确认其存在、无引用，且删除属于当前任务范围。

## 15. AI 任务完成报告

每个任务完成后使用以下结构汇报，并停止等待用户确认：

```text
任务：Txx - 任务名称
状态：完成 / 阻塞

变更文件：
- 文件路径：变更目的

验证结果：
- 命令或检查项：通过 / 失败及关键证据

可见效果：
- 用户当前能够看到或操作的效果

范围检查：
- 已确认未实现后续任务或范围外功能

遗留与阻塞：
- 无；或列出具体问题、证据及需要用户决定的事项
```

报告后必须等待用户确认。除非用户明确指定下一个任务，否则不得继续实现。
